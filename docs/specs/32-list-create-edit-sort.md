# Фаза 7: Вкладка «Список» — создание, редактирование, удаление, группы, сортировка

**Issue:** [#32](https://github.com/shhhwepsss/eisenhower-todo/issues/32)  
**Зависит от:** Фаза 4 (стор и селекторы)  
**Архитектурные разделы:** [docs/specs/4-architecture.md](./4-architecture.md) §2, §5, §9, §11

## Задача

Реализовать вторую вкладку приложения — полный инвентарь задач в виде списка с тремя группами, работой с текстом задачи и статусом, сортировкой внутри групп. Это единственное место в MVP, где можно создать и удалить задачу.

Сортировка выбирается в UI, но не сохраняется между сессиями — сохранение идёт отдельно в фазе 8.

## Скоуп

**In:**

- Создание задачи: поле ввода с заголовком (до 300 символов, одна строка), нажатие Enter создаёт задачу в группе «Входящие». По PRD S1 признаки не требуются: новая задача всегда `assigned: false, urgent: false, important: false, status: 'todo'`.
- Редактирование: щелчок на карточку открывает попап/боковую панель с полями заголовка (то же ограничение), описания (неограниченное), признаков (`assigned`, `urgent`, `important`), статуса, кнопок удаления и сохранения. При редактировании описания `updatedAt` сдвигается.
- Удаление задачи: кнопка в попапе удаления или свайп (если реализовано). Удалённая задача получает `deletedAt: now()` и не видна нигде (инвариант `DELETE_IS_A_TOMBSTONE`).
- Три группы в фиксированном порядке:
  - «Входящие» — `assigned: false`.
  - «В квадранте» — `assigned: true`.
  - «Выполненные» — `status: 'done'`.
- Сортировка внутри группы: четыре варианта, выбор в UI, но не персистится (фаза 8).
  - По дате создания (дефолт) — `createdAt DESC`.
  - По алфавиту — `title ASC, id ASC` (вторичный ключ на случай одинаковых заголовков).
  - По статусу — `(todo, in_progress, done), id ASC` (в каждой группе свой порядок может быть другой, но обычно дефолт).
  - По квадранту — Q1, Q2, Q3, Q4, затем Q-less (`assigned: true, status: 'todo'` не в квадранте) — `(quadrant, id) ASC`.
- Выбор сортировки не трогает снапшот задач и не сдвигает `updatedAt` — инвариант `DERIVED_ORDER_IS_NOT_STORED`.
- Переключение статуса в списке немедленно видно в матрице (фаза 5) — инвариант `SINGLE_SOURCE_OF_TRUTH`.

**Out:**

- Сохранение выбранной сортировки между перезагрузками — фаза 8.
- Поиск по тексту или фильтры по признакам.
- Массовые операции (например, пометить все как выполненные).
- Перетаскивание в списке — не входит в PRD §3.
- Скорочтение и форматирование Markdown в описании.

## Инварианты

**`LIST_IS_COMPLETE`** (спека §2, §9) — в списке видны все живые задачи без исключения, кроме удалённых (`deletedAt IS NULL`). Селектор `getListTasks()` не фильтрует ничего, кроме удаления. Проверяется свойством-тестом: объединение трёх групп списка = все живые задачи; матрица и список видят одно и то же для каждого статуса и признаков.

**`LIST_PARTITION`** (спека §2, §9) — три группы образуют разбиение на множестве живых задач:
- Без пересечений: задача не может быть одновременно во «Входящих» (где `assigned: false`) и «В квадранте» (где `assigned: true`).
- Полное покрытие: каждая живая задача попадает в ровно одну из трёх групп.

Гарантируется типом `ListGroup = 'inbox' | 'assigned' | 'done'`, из которого вычисляется группа функцией `getTasksListGroup(task)`.

**`SINGLE_SOURCE_OF_TRUTH`** (спека §5, §9) — изменение задачи в списке (редактирование, удаление, переключение статуса или признаков) немедленно видно в матрице, если та же задача там показана. Нет копии задачи в локальном состоянии компонента — редактор работает со снапшотом текущего состояния из стора, и при сохранении действие обновляет редьюсер целиком.

**`DERIVED_ORDER_IS_NOT_STORED`** (спека §2, §8, §9) — порядок внутри группы — результат сортировки по выбранному критерию, который берётся из `ui.listSort`. Смена сортировки не записывает новые значения в `rank` задач и не сдвигает их `updatedAt`. Проверяется: перейти в матрицу и вернуться в список — если порядок в группе изменился, а в матрице нет — порядок действительно производный.

**`STATE_ACCESS_VIA_HOOKS`** (спека §5, §9) — компонент получает список задач и действия через хуки: `useListGroup(group)` для каждой из трёх групп, `useListSort()` для выбора сортировки, `useTaskActions()` для редактирования. Прямой импорт из контекста или редьюсера запрещён.

**`DELETE_IS_A_TOMBSTONE`** (спека §2, §9) — удалённая задача не удаляется из массива `tasks`, а получает флаг `deletedAt`. Это даёт место для отката (не в MVP, но место уже подготовлено) и гарантирует, что ID удалённой задачи не переиспользуется в той же сессии — инвариант `ID_IS_GLOBALLY_UNIQUE`.

## Критерии приёмки

- [ ] **GIVEN** пустой список и фокус на поле «Введите заголовок» **WHEN** введён «Купить молоко» и нажат Enter **THEN** задача создана в группе «Входящие» с `assigned: false, urgent: false, important: false, status: 'todo'`, поле очищено и готово к следующему вводу.
- [ ] **GIVEN** созданная задача видна в списке и в матрице во «Входящих** **WHEN** в матрице выставлены `urgent: true` и `important: true` **THEN** в списке задача мгновенно перепрыгивает в группу «В квадранте», остальные свойства не изменились — `SINGLE_SOURCE_OF_TRUTH`.
- [ ] **GIVEN** задача с `status: 'todo'` **WHEN** статус переключена в `done` в списке **THEN** задача исчезает из групп «Входящие» и «В квадранте», появляется в группе «Выполненные**, и в матрице её уже нет нигде — `DONE_LEAVES_MATRIX` соблюдается.
- [ ] **GIVEN** три задачи в группе и выбрана сортировка по дате создания **WHEN** выбрана алфавитная сортировка **THEN** порядок в каждой из трёх групп стал алфавитным, группы на месте (порядок групп не меняется, только порядок внутри групп).
- [ ] **GIVEN** алфавитная сортировка активна **WHEN** две задачи имеют один и тот же заголовок **THEN** вторичный ключ сортировки — `id`, и порядок консистентен (не скачет при перезагрузке).
- [ ] **GIVEN** задача во «Входящих** **WHEN** щелчок на карточку, открыт редактор, описание задано, сохранено **THEN** описание сохранено в задачу, `updatedAt` сдвинут, но `rank` остался прежним — `DERIVED_ORDER_IS_NOT_STORED`.
- [ ] **GIVEN** задача в списке **WHEN** кнопка удаления в редакторе, подтверждение **THEN** задача исчезает из всех групп списка и из матрицы, при перезагрузке не возвращается — `DELETE_IS_A_TOMBSTONE`.
- [ ] **GIVEN** сортировка переключена на «По квадранту** **WHEN** две задачи, одна в Q1 одна в Q4 **THEN** в группе «В квадранте» Q1 раньше Q4 согласно табличке квадрантов.
- [ ] **GIVEN** выбрана сортировка, задача отредактирована (описание) **WHEN** страница перезагружена **THEN** сортировка сбросилась на дефолт «По дате» (фаза 8 её сохранит).
- [ ] `lint`, `build`, `test` проходят.
- [ ] Прогон в браузере (сценарии PRD S1, S4a, S5), скриншоты прикреплены в PR.

## Крайние случаи

| Случай | Поведение |
|---|---|
| Заголовок пуст или только пробелы | При создании проверить `trim().length > 0`; не позволить создать пустую задачу. При редактировании — позволить сохранить, но отобразить заголовок как пусто |
| Заголовок больше 300 символов | Ограничить поле максимальной длиной. Обрезать при попытке вставить; строка обрезалась при копипасте |
| Описание очень большое (МБ текста) | `localStorage` имеет квоту. Остановить редактор заранее, не давая заполнить свыше разумного. Тесты на переполнение квоты — отдельно (инвариант `STORAGE_FAILURE_IS_VISIBLE`) |
| Две группы пусты, одна содержит задачи | Пусть показывают пустые группы. Не скрывать заголовки групп, даже если в них нет задач — это помогает изучить интерфейс |
| Сортировка изменена, но задач нет | Выпадающий список работает; при появлении первой задачи она встанет в правильное место согласно выбранной сортировке |
| Задача удалена и создана новая с похожим названием | Новая задача получит новый UUID; старая остаётся надгробием. Для пользователя — разные задачи. В списке видна только новая |

## Реализованные расхождения с GitHub-issue

Текущая реализация содержит три группы, сортировку, редактирование, удаление. Все критерии приёмки фазы 7 выполнены. Специфика реализации может расходиться с описанием (например, поп-ап против боковой панели), но внешний контракт соблюдён.
