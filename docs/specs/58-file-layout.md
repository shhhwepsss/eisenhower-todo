# #58 — Раскладка файлов: типы, константы, lib и сервисы

## Задача

Типы, константы, lib-модули и сервисы лежат каждый в своей папке с суффиксом в имени
файла, и это проверяет ESLint, а не ревью.

## Прототип

Не требуется.

## Решения

Приняты человеком 2026-10-03.

- **Папка и суффикс вместе.** Вид файла читается из имени без открытия: в поиске по
  файлам `zone.type.ts` и `zone.lib.ts` не путаются, а папка собирает однородное рядом.

  | Папка        | Суффикс файла  |
  | ------------ | -------------- |
  | `types/`     | `*.type.ts`    |
  | `constants/` | `*.constant.ts`|
  | `lib/`       | `*.lib.ts`     |
  | `services/`  | `*.service.ts` |

  Единственное число в суффиксе. `index.ts` в каждой из папок — без суффикса, это
  публичный вход папки, а не её содержимое.
- **Правило строгое: проверяется не только имя, но и объявления.** Объявление `type` /
  `interface` / `enum` — только в `*.type.ts`; константа верхнего уровня с именем
  `UPPER_CASE` — только в `*.constant.ts`. Иначе папки были бы, а типы и константы
  продолжали бы жить где попало — правило про имя файла этого не замечает.
  Пропсы компонента — тоже тип, и тоже уезжают в `types/` рядом с компонентом.
- **`*.type.ts` содержит только типы.** Рантайм-кода в нём нет — иначе «файл типов»
  перестал бы значить «его можно импортировать как `import type`».
- **`helpers/` → `lib/`.** Это одно и то же; две папки для чистых функций — повод
  каждый раз выбирать, куда класть.
- **Что такое lib и сервис, линтер не знает.** Он проверяет только, что `*.lib.ts`
  лежит в `lib/`, а в `lib/` лежат только `*.lib.ts` (и так же для сервисов). Решение
  «это lib или нет» — на ревью.
- **Правило — локальный плагин ESLint без зависимостей**
  (`eslint.file-layout.js` в корне). Готовые плагины (`eslint-plugin-check-file`)
  проверяют только имя и папку, объявления — нет; их всё равно пришлось бы дописывать.
- **Правило — в `baseConfig`, а не по выбору пакета** (2026-10-03). Общее для фронта и
  бека живёт в корневой базе, своё — в `eslint.config.js` пакета, который базу
  расширяет. Подключение по выбору означало бы, что новый пакет получает правило, когда
  о нём вспомнили: `apps/api` (PR #56) так и появился без него. Поэтому перенос
  `apps/web` идёт в той же фазе, без временного выключения.
- **Область — `src/` пакетов.** `tests/` и конфиги (`vite.config.ts`,
  `eslint.config.js`) не проверяются: тест держит свои фикстуры и локальные типы
  рядом с проверкой, а конфиг — один файл по определению. `*.d.ts` — тоже нет.

## Скоуп

**In**

- Плагин `eslint.file-layout.js` с четырьмя правилами (см. инварианты); конфиг
  `fileLayout` для `src/**/*.{ts,tsx}` входит в `baseConfig`.
- Тесты правил в `packages/core/tests/file-layout.test.ts` — как
  `package-boundaries.test.ts`: реальный конфиг по коду, которого в репозитории нет.
- Перенос `packages/core`: `types/*.ts` → `types/*.type.ts`, `constants/*.ts` →
  `constants/*.constant.ts`, `TaskPatch` из `mutations.ts` → `types/task-patch.type.ts`.
- Перенос `apps/web`: суффиксы в существующих `types/` и `constants/`; `helpers/` →
  `lib/` с суффиксом `*.lib.ts`; типы и константы `UPPER_CASE` из остальных файлов —
  в `types/` и `constants/` своего слайса или слоя. У каждой `types/` — баррель
  `index.ts`; типы не реэкспортируются через хуки, `lib/` или `constants/`.
- `COMPARATORS` сортировки списка зависят от функций сравнения, поэтому раскладка в
  три файла без цикла импортов: `lib/list-comparators.lib.ts` (сравнения) ←
  `constants/list-comparators.constant.ts` (таблица) ← `lib/list-order.lib.ts`
  (сортировка).
- `CLAUDE.md` §8 — правило раскладки; README — раскладка кода.

**Out**

- `apps/api` — живёт в PR #56. Правило приходит к нему из базы при слиянии с
  `production`; три нарушения (`HealthBody`, `BUILD_VERSION` в `app.ts`, `SEVERITY`
  в логгере) правятся в #56.
- Раскладка остальных файлов (`hooks/`, `children/`, корневые модули слоя вроде
  `zone.ts` или `reducer.ts`) — правило их не трогает.
- Проверка содержимого `lib/` и `services/` — не делаем, см. «Решения».

**Допущения**

- Перенос — чистые переименования и переезд объявлений; поведение не меняется.

## Инварианты

- `BEHAVIOR_PRESERVED`: перенос не меняет поведения; тесты зелёные без правок логики —
  меняются только импорты и пути.
- `FILE_IN_ITS_FOLDER`: файл `*.type.ts` / `*.constant.ts` / `*.lib.ts` / `*.service.ts`
  лежит прямо в папке своего вида, а в папке вида лежат только файлы с её суффиксом и
  `index.ts`.
- `TYPES_LIVE_IN_TYPE_FILES`: `type`, `interface`, `enum` объявляются только в
  `*.type.ts`.
- `TYPE_FILES_HOLD_ONLY_TYPES`: в `*.type.ts` нет рантайм-кода.
- `CONSTANTS_LIVE_IN_CONSTANT_FILES`: константа верхнего уровня с именем `UPPER_CASE`
  объявляется только в `*.constant.ts`.

  его конфига.
- [x] После каждой фазы `npm run lint`, `npm run build`, `npm test` из корня зелёные.
