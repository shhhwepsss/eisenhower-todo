# Фаза 5: Вкладка «Матрица» — зоны, карточки, разбор переключателями

**Issue:** [#30](https://github.com/shhhwepsss/eisenhower-todo/issues/30)  
**Зависит от:** Фаза 4 (стор и селекторы)  
**Архитектурные разделы:** [docs/specs/4-architecture.md](./4-architecture.md) §5, §11

## Задача

Вывести первый рабочий экран приложения: вкладка «Матрица» с зоной «Входящие» рядом с четырьмя квадрантами, разбором задач переключателями срочности и важности, порядком входящих по дате создания. Перетаскивание реализуется отдельно в фазе 6.

## Скоуп

**In:**

- Макет матрицы: зона «Входящие» рядом с четырьмя квадрантами Эйзенхауэра (Q1–Q4).
- Карточка задачи: заголовок, переключение статуса `todo ↔ done`, переключатели срочности и важности.
- Назначение квадранта переключателями: при проставлении обоих признаков задача встаёт в конец целевого квадранта с вычисленным рангом.
- Завершённые задачи (`status: 'done'`) не видны нигде на вкладке, включая «Входящие» — инвариант `DONE_LEAVES_MATRIX`.
- Порядок входящих — по `createdAt`, новые сверху. Вычисляется каждый раз, в рангу не пишется — инвариант `DERIVED_ORDER_IS_NOT_STORED`.
- Сообщение об ошибке хранилища (статус `'error'`) — видно сверху или отдельным экраном.
- Лоадер вместо вкладок пока `storage: 'loading'` (спека решение 6 §12).

**Out:**

- Перетаскивание (жест на карточке) — фаза 6. До неё квадранты работают только переключателями; возврат задачи из квадранта во «Входящие» возможен только через перетаскивание.
- Создание, редактирование и удаление задачи — фаза 7 (вкладка «Список»).
- Сортировка списка и её сохранение — фазы 7 и 8.
- Поиск, фильтры, массовые операции.

## Инварианты

**`MATRIX_PARTITION`** (спека §2) — каждая невыполненная и неудалённая задача видна ровно в одной зоне матрицы: либо во «Входящих», либо в одном из квадрантов. Селектор `resolveZone(task)` возвращает ровно один из пяти вариантов `Zone` по типу. Гарантируется: объединение результатов четырёх селекторов квадрантов и входящих не содержит пересечений и покрывает все живые и необработанные задачи.

**`DONE_LEAVES_MATRIX`** (спека §2) — задача со статусом `done` не появляется ни в выборке «Входящих» (`useInboxTasks()`), ни в выборке квадранта (`useQuadrantTasks(quadrant)`). Проверяется в селекторах, а не в разметке — нет условного рендера `{!task.done &&}`, который забывают.

**`DERIVED_ORDER_IS_NOT_STORED`** (спека §2, §9) — порядок входящих берётся из селектора `useInboxTasks()` (сортировка по `createdAt` desc), задача не получает поля `indexInInbox` или индекса в JSON. Смена сортировки (фаза 8) не трогает это свойство.

**`STATE_ACCESS_VIA_HOOKS`** (спека §5, §9) — компонент получает данные и действия только через хуки (`useInboxTasks()`, `useQuadrantTasks()`, `useTaskActions()`, `useStorageStatus()`), а не напрямую из контекста или редьюсера. Импорт из `state/` ограничен точкой входа. Проверяется ESLint-правилом `no-restricted-imports`.

**`STATE_ACCESS_VIA_HOOKS` + `SINGLE_SOURCE_OF_TRUTH`** (спека §5) — изменение задачи в матрице немедленно отражается, если та же задача откроется в списке (фаза 7). Копии задачи в местном state компонента нет.

**`MATRIX_PARTITION`** следует из реализации: селекторы квадрантов исключают `status === 'done'`, статус не меняется вне действия `setStatus()`. Проверяется компилятором (сумма-тип `Zone`) и свойством-тестом: сумма размеров пяти зон = счёт живых не-`done` задач.

## Критерии приёмки

- [ ] **GIVEN** пустая матрица **WHEN** создана задача во «Входящих» **THEN** она видна в зоне «Входящие».
- [ ] **GIVEN** задача во «Входящих** **WHEN** обе переключателя срочности и важности выставлены в состояние, соответствующее Q1 **THEN** задача исчезает из «Входящих» и появляется в Q1, в конце списка, с вычисленным рангом.
- [ ] **GIVEN** три задачи во «Входящих**, созданные в разные моменты **WHEN** вкладка отрисована **THEN** порядок — по убыванию `createdAt` (новые сверху).
- [ ] **GIVEN** задача в квадранте **WHEN** статус переключён в `done` **THEN** задача исчезает со вкладки целиком, из всех зон.
- [ ] **GIVEN** задача в `done` **WHEN** статус переключён обратно в `todo` **THEN** задача вернулась в Q4 (в конец списка), признаки `urgent` и `important` остались на месте — `PRIORITY_SURVIVES_DONE`.
- [ ] **GIVEN** несколько задач в Q1 **WHEN** переключены различные признаки на их карточках **THEN** порядок в квадранте не изменился (признаки не меняют ранг).
- [ ] **GIVEN** хранилище недоступно (`storage: 'error'`) **WHEN** вкладка отрисована **THEN** видно сообщение об ошибке, работать с задачами нельзя.
- [ ] **GIVEN** приложение стартует **WHEN** хранилище ещё загружается (`storage: 'loading'`) **THEN** вместо вкладок видна загрузка (лоадер), вкладки смонтированы только когда статус перейдёт в `'ready'`.
- [ ] `lint`, `build`, `test` проходят.
- [ ] Прогон в браузере (сценарии PRD S3, S6, S6a), скриншоты прикреплены в PR.

## Крайние случаи

| Случай | Поведение |
|---|---|
| Задача попадает одновременно из фазы 7 (список) и фазы 6 (перетаскивание) | Редьюсер обработает оба действия последовательно; консистентность выборки гарантируется селекторами, а не координацией экранов |
| Поле `deleted_at` появляется при загрузке | Селекторы исключают задачи `where deleted_at IS NOT NULL`; надгробие не видно в матрице |
| Признаки снимаются в разном порядке (сначала `urgent`, потом `important`) | `MANUAL_PRIORITISATION`: признаки меняет только `setPriority()`, а не побочный эффект изменения статуса. Каждое действие приносит консистентное состояние. Задача не подпрыгивает между квадрантами при промежуточных состояниях |
| Матрица попытается добавить одну и ту же задачу дважды (race condition) | Не может произойти: мутации последовательны (React события синхронны, редьюсер синхронен), конкурент только — вторая вкладка, и она вне скоупа (PRD §6) |

## Реализованные расхождения с GitHub-issue

В текущей реализации на ветке `feature/mvp` матрица уже содержит контекст `DndContext` из `@dnd-kit` (фаза 6), хотя согласно спеке перетаскивание идёт отдельно. Это сознательное решение разработчика: поддерживать возможность перетаскивания на протяжении всех фаз. Критерии приёмки фазы 5 остаются без изменений — перетаскивание кода фазы 5 не повинно.
