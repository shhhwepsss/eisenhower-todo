# Пользователь — `users`

Состояние: **запланирована**, появляется в #52, фаза 1. Спека:
`docs/specs/52-google-auth.md`.

## Что это

Человек, вошедший в приложение. Строку создаёт Auth.js при первом входе через Google;
её `id` — владелец всего, что пользователь создаст дальше (задачи — #46).

## Колонки

| Колонка          | Тип              | Пусто | Смысл                                                    |
| ---------------- | ---------------- | ----- | -------------------------------------------------------- |
| `id`             | `text`           | нет   | UUID, генерируется приложением при создании              |
| `name`           | `text`           | да    | имя из профиля Google на момент первого входа            |
| `email`          | `text`           | да    | почта из профиля Google                                  |
| `email_verified` | `timestamp`      | да    | требует адаптер; при входе через Google остаётся `NULL`  |
| `image`          | `text`           | да    | адрес аватара из профиля Google                          |
| `created_at`     | `timestamptz(3)` | нет   | время первого входа, ставит база (`DEFAULT now()`)       |

Набор и типы первых пяти колонок задаёт контракт адаптера Auth.js
(`@auth/drizzle-adapter`, `src/lib/pg.ts`): убрать или переименовать свойство нельзя.
`created_at` — наша.

## Ключи и ограничения

- Первичный ключ — `id`.
- `email` — `UNIQUE`.

## Связи

- `accounts.user_id → users.id`, `ON DELETE CASCADE` — [аккаунт](account.md).
- `tasks.user_id → users.id` — #46.

## Кто пишет, кто читает

- **Пишет** только адаптер Auth.js при входе (`apps/api/src/db/neon/`): `createUser` при
  первом входе. Код приложения строку не меняет.
- **Читает** адаптер при входе. `GET /api/me` и проверка сессии таблицу не читают:
  `id`, `name`, `email` лежат в JWT-cookie (`SESSION_CHECK_SKIPS_DATABASE`).

## Инварианты

- `ONE_USER_PER_GOOGLE_ACCOUNT`: один аккаунт Google — одна строка. Держится `UNIQUE`
  на `email` и первичным ключом `accounts`.
- `id` не меняется: он записан в `sub` каждой выданной сессии и станет внешним ключом
  задач.

## Жизненный цикл

Статусов нет. Строка создаётся при первом входе и живёт дальше без изменений.

Следствие: `name`, `email`, `image` — снимок на момент первого входа. Сменил имя в
Google — в базе старое; в новой сессии — то, что в базе.

## Чего здесь нет

- Пароля: вход только через Google.
- Ролей и прав: пользователь один.
- Удаления аккаунта.
- Настроек интерфейса: тема и сортировка остаются на устройстве (#46).
